# v3.8.0 masterdata export handoff

## Scope and evidence

Compared the v3.8.0 C# dump `825291bd10516ececb797378fdc51efb930b04ef`
against v3.7.1 `ccc9db682`. The v3.8.0 binary is from
`RaenonX-PokemonSleep/pokemon-sleep-apk-dumper@0f6a8016a8dbea5153793083e38482cc4fc8bdbb`.

This is an **APK client capability/schema comparison**, not a comparison of two
downloaded masterdata releases. Actual server-delivered rows, masterdata version,
values, SQLite declared types, constraints, and physical column order have not
been verified here. Do not use `Added: v3.8.0` in the newly bootstrapped catalog
alone to identify release additions: many existing masterdata fields have that
observation date. The additions below were checked against the preceding C# dump.

Native static initializers establish the literal SQL names. Row readers and model
constructors establish client value types. All tables below use the **masterdata**
connection, except the explicitly separated user-data change at the end.

## Four new tables

### `event_berries`

| SQL column | Client property | Client value |
| --- | --- | --- |
| `id` | `EventBerry.Id` | Int32 |
| `event_id` | `EventBerry.EventId` | Int32 |
| `berry_id` | `EventBerry.BerryId` | Int32 |

Associates an event with a berry. Preserve the row ID and both references; resolve
event dates through the existing event join helper if the downstream contract
needs them. Do not assume `event_id` is unique without inspecting the data.

**Use `event_berries`, not `event_berry`.** The latter was an incorrect candidate
generated by converting `EventBerryManager` to snake_case.

Source: `Dumped/EventBerry.cs`, `Dumped/EventBerryManager.cs`; initializer at
ARM64 virtual address `0x058CA5A0` in the specified v3.8.0 binary.

### `main_skill_berry_zone`

| SQL column | Client property | Client value |
| --- | --- | --- |
| `id` | `MainSkillBerryZone.Id` | Int32 |
| `main_skill_ids` | `MainSkillBerryZone.SkillIds` | Int32[] after parsing |
| `berry_pokemon_types_id` | `MainSkillBerryZone.TypeId` | Int32 |
| `rate_max` | `MainSkillBerryZone.RateMax` | Int32 |

The native reader accepts an integer or a comma-separated string for
`main_skill_ids`; the constructor splits on comma and parses integers. Export an
array of numeric skill IDs while retaining the original row ID. The type column
is a Pokemon type identifier, not a berry row ID. Keep the type dimension when
grouping records: the client exposes `GetMaxRate(mainSkillId, typesId)` as well as
a skill-only lookup. Do not collapse multiple rows to one rate without checking
their type and skill memberships.

`GetParamWithSkillId` performs delimiter-aware membership matching using
`(',' || main_skill_ids || ',') LIKE '%,<skillId>,%'`.

Source: `Dumped/MainSkillBerryZone.cs`, `Dumped/MainSkillBerryZoneManager.cs`.
The exact type-column spelling is `berry_pokemon_types_id`, not `types_id`.

### `main_skill_berry_zone_param`

| SQL column | Client property | Client value |
| --- | --- | --- |
| `id` | `MainSkillBerryZoneParam.Id` | Int32 |
| `main_skill_id` | `MainSkillBerryZoneParam.MainSkillId` | Int32 |
| `level` | `MainSkillBerryZoneParam.Level` | Int32 |
| `energy` | `MainSkillBerryZoneParam.Energe` | Int32 |
| `add_rate` | `MainSkillBerryZoneParam.AddRate` | Int32 |

The manager looks up records by `main_skill_id` and `level`. These supply
skill-level parameters for the berry-zone feature. Preserve `energy`, `add_rate`,
and `rate_max` as raw integers; this handoff does not establish a percentage scale,
duration, complete stacking formula, or the numerical contents of any row.

**The SQL column is `energy`.** `Energe` and `COL_ENERGE` are C# spelling errors.

Source: `Dumped/MainSkillBerryZoneParam.cs`,
`Dumped/MainSkillBerryZoneParamManager.cs`; initializer at `0x0590E9F8`.

### `pokedex_sleeping_face`

| SQL column | Client property | Client value |
| --- | --- | --- |
| `id` | `PokedexSleepingFace.Id` | Int32 |
| `sleeping_face_id` | `PokedexSleepingFace.SleepingFaceId` | Int32 |
| `field_address` | `PokedexSleepingFace.FieldAddress` | String |
| `field_thumb_address` | `PokedexSleepingFace.FieldThumbAddress` | String |
| `research_anim_address` | `PokedexSleepingFace.ResearchAnimAddress` | String |

Provides sleep-style presentation asset references. Preserve address strings
verbatim; they are asset addresses, not automatically web URLs. Keep `id` and
`sleeping_face_id` distinct. The manager exposes `GetBySleepingFaceId` and
`GetAllResourcesSafe`; this handoff does not infer missing-table behavior from the
latter's name. Handle missing or empty deployed data explicitly when validating
the exporter rather than fabricating rows or addresses.

Source: `Dumped/PokedexSleepingFace.cs`, `Dumped/PokedexSleepingFaceManager.cs`.
The native Row reader passes two integer reads and three string reads into the
model constructor in the order shown above.

## Existing masterdata changes

### `berries`: two additional columns

| New SQL column | Client property | Verified behavior |
| --- | --- | --- |
| `is_event` | `Berry.IsEvent` | Constructor converts the integer using `isEvent != 0` |
| `base_id` | `Berry.BaseId` | Integer used by `GetResourceAddress()` |

Existing columns remain `id`, `name`, `pokemon_types_id`, and `desc`.
`Berry.GetResourceAddress()` formats
`Images/ItemThumbnails/Foods/food_{base_id}.png`, using `BaseId` rather than `Id`.
`BerryManager` also adds `GetNormalBerries()` with a zero-valued event-flag filter.

Exporter implication: preserve event berries in the raw data, expose their event
flag and base ID, and distinguish any ordinary-berry selection from the complete
berry catalog. **Do not assume `base_id` supplies berry energy data**: its resource
address use is confirmed here, but energy inheritance is not.

Source: `Dumped/Berry.cs`, `Dumped/BerryManager.cs`; constructor `0x059AF5A0`,
resource-address method `0x059AF7E8`.

### `snack_time_buff`: `pokemon_ids`

Existing columns are `id` and `event_id`. The new `pokemon_ids` column is read as
a string and mapped to `EventSnackTimeBuff.PokemonIds` (Int32[]). The constructor
checks null/empty input and has a string-splitting path. Preserve this targeting
data instead of exporting only event dates. Do not infer the meaning of an empty
target list from the column name alone or equate these internal Pokemon IDs with
the downstream Pokedex IDs without the existing mapping.

The real table name is `snack_time_buff`, not `event_snack_time_buff`.
Source: `Dumped/EventSnackTimeBuff.cs`, `Dumped/EventSnackTimeBuffManager.cs`.

### `other_parameters_for_client`: new accessor, no column addition

`GetParam4()` was added. Its native code loads key `param_4`, trims the retrieved
value, calls `TextUtils.SpoilerDecrypt`, and parses an optional Int32. The table's
columns remain `id`, `key`, and `value`. This proves client support for that key,
not that a current masterdata payload contains it or what gameplay quantity it
represents. Preserve the raw value; do not blindly cast it before decoding.

Source: `Dumped/OtherParametersForClientManager.cs`; `GetParam4` at `0x0591DE1C`.

The other modified masterdata managers in the commit (`EventStoryManager` and
`EventTradeItemSleepingFacesManager`) add no `COL_*` fields. No removed `COL_*`
fields were found among the changed masterdata managers.

## Suggested exporter work in `pokemon-sleep-scraper`

1. Load the four new tables with explicit column selections shown below; preserve
   row IDs and raw rate values. Confirm their presence in the downloaded SQLite
   database before choosing output collection contracts or uniqueness indexes.
2. Add event-berry export alongside `scrape/module/event/` and reuse
   `scrape/module/event/utils/join.py` for date joins as appropriate.
3. Add berry-zone parameter loading under `scrape/module/mainskill/context/effect/`
   and wire it through `scrape/module/mainskill/context/main.py`. Keep the skill
   membership array, type ID, and level axes explicit.
4. Update `scrape/module/berry.py`: it currently starts from `berry_energy` and
   only takes the type mapping from `berries`. That flow does not export
   `is_event` or `base_id`, and may omit event berries with no independent energy
   rows. Inspect real data before deciding the energy relationship.
5. Update `scrape/module/event/snack_delay_full.py`: it already reads
   `snack_time_buff` but only emits IDs and event dates, dropping `pokemon_ids`.
   Existing event exporters show how to map internal IDs to downstream Pokedex IDs.
6. Export `pokedex_sleeping_face` asset references alongside sleep-style data;
   register a new standalone export module in `scrape/main.py` if needed.

Use the existing `open_sql_connection`, `load_dataframe_from_sql`,
`start_export_module`, and `export_to_mongo` helpers. This handoff makes no changes
to the scraper and does not perform MongoDB writes or downloads.

```sql
SELECT id, event_id, berry_id FROM event_berries;
SELECT id, main_skill_ids, berry_pokemon_types_id, rate_max
FROM main_skill_berry_zone;
SELECT id, main_skill_id, level, energy, add_rate
FROM main_skill_berry_zone_param;
SELECT id, sleeping_face_id, field_address, field_thumb_address,
       research_anim_address FROM pokedex_sleeping_face;
SELECT id, name, pokemon_types_id, desc, is_event, base_id FROM berries;
SELECT id, event_id, pokemon_ids FROM snack_time_buff;
SELECT id, key, value FROM other_parameters_for_client WHERE key = 'param_4';
```

## Separate user-data change

`user_main_skill` adds `EffectValueRate INTEGER` via
`PS.Migration.Server.Migration202607071801UserMainSkillAddColumn`.
This is **user data in the server connection**, not a new masterdata table.
Do not include it in a masterdata exporter merely because its migration SQL appears
in the same APK metadata catalog.
